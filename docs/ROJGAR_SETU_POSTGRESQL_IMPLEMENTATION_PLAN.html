02 The PostgreSQL Spatial Engine: Replacing 2dsphere with PostGIS GiST

In MongoDB, spatial proximity relies on 2dsphere indexes and GeoJSON. In PostgreSQL, the exact, more powerful industry-standard replacement is PostGIS utilizing the GEOGRAPHY(Point, 4326) data type indexed with a GiST (Generalized Search Tree) index.

Operation MongoDB Approach PostgreSQL + PostGIS Approach Engineering Benefit in PostgreSQL
Spatial Type { type: "Point", coordinates: [lng, lat] } GEOGRAPHY(Point, 4326) WGS-84 native ellipsoid modeling; handles true curvature of Earth without planar distortion.
Spatial Index db.jobs.createIndex({ location: "2dsphere" }) CREATE INDEX idx_jobs_gist ON jobs USING GIST (location); R-Tree bounding box hierarchy. Sub-millisecond lookup times over millions of coordinate points.
Radius Query $near: { $maxDistance: 3000 } ST_DWithin(location, ST_MakePoint(lng, lat)::geography, 3000) Standard SQL syntax. Can be joined directly with relational tables in a single query.
Exact Distance Calculated via Aggregation Pipeline ST_Distance(location, user_point) (returns meters) Calculated inline; sortable with ORDER BY distance_meters ASC.

-- USERS TABLE (Central Authentication & Identity)

    is_phone_verified BOOLEAN DEFAULT FALSE,

CREATE INDEX idx_users_phone ON users (phone);

-- WORKER PROFILES TABLE (Karigar Unified Profile)
CREATE TABLE worker_profiles (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID UNIQUE NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    karigar_id VARCHAR(30) UNIQUE NOT NULL,  -- e.g. "RS-DEL-8821"
    primary_trade VARCHAR(80) NOT NULL,      -- "Electrician", "House Maid", "Gardener"
    
    -- JSONB column for trade-specific skills without table bloat
    -- Electrician: {"wiring": true, "3phase": true, "has_tools": true}
    -- Maid: {"jhadu_pochha": true, "bartan": true, "cooking": "veg_only"}
    -- Gardener: {"lawn_mower": true, "pruning": true, "potting": true}

    wage_type wage_basis DEFAULT 'daily',
    expected_wage NUMERIC(10, 2) NOT NULL,
    is_available BOOLEAN DEFAULT TRUE,
    
    -- PostGIS Spherical Geography Point + GiST Index
    location GEOGRAPHY(Point, 4326) NOT NULL,
    city VARCHAR(80) NOT NULL,
    locality VARCHAR(120) NULL,              -- Society / Mohalla / Colony
    pincode VARCHAR(10) NULL,
    
    -- Verification Badges (DigiLocker, AI MCQ, Police)
    -- Example: {"digilocker_verified": true, "aadhaar_name": "Ramu", "mcq_score": "3/3", "skill_badge": "Certified Pro"}
    verification_badges JSONB NOT NULL DEFAULT '{}'::jsonb,
    
    rating_avg NUMERIC(3, 2) DEFAULT 5.00,
    total_reviews INT DEFAULT 0,
    bio TEXT NULL,
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

-- CREATE POSTGIS GIST INDEX ON WORKER LOCATION
CREATE INDEX idx_worker_location_gist ON worker_profiles USING GIST (location);
CREATE INDEX idx_worker_skills_gin ON worker_profiles USING GIN (skills);
CREATE INDEX idx_worker_trade ON worker_profiles (primary_trade, is_available);

-- JOBS TABLE (Supports both MSME Construction & Household Domestic Gigs)
CREATE TABLE jobs (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    employer_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    title VARCHAR(200) NOT NULL,
    category VARCHAR(80) NOT NULL,           -- "Maid / Housekeeping", "Electrician", "Gardener"
    
    -- Sub-services requested (JSONB)
    -- e.g. ["Jhadu-Pochha", "Bartan", "Dusting"]
    sub_services JSONB NOT NULL DEFAULT '[]'::jsonb,
    
    timing_type VARCHAR(50) DEFAULT 'full_day', -- 'morning_shift', 'evening_shift', 'weekend_gig'
    preferred_timings VARCHAR(100) NULL,        -- "07:30 AM - 09:30 AM"
    
    vacancies INT DEFAULT 1,
    wage_offered NUMERIC(10, 2) NOT NULL,
    wage_period wage_basis DEFAULT 'daily',
    description TEXT NOT NULL,
    
    -- PostGIS Spherical Geography Point
    location GEOGRAPHY(Point, 4326) NOT NULL,
    city VARCHAR(80) NOT NULL,
    locality VARCHAR(120) NULL,              -- "Sector 62, Grand Omaxe Society"
    pincode VARCHAR(10) NULL,
    
    status VARCHAR(20) DEFAULT 'active',     -- 'active', 'filled', 'closed'
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

-- CREATE POSTGIS GIST INDEX ON JOB SITE LOCATION
CREATE INDEX idx_jobs_location_gist ON jobs USING GIST (location);
CREATE INDEX idx_jobs_category_status ON jobs (category, status);

-- APPLICATIONS TABLE (Candidate Hiring & Screening Pipeline)
CREATE TABLE applications (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    job_id UUID NOT NULL REFERENCES jobs(id) ON DELETE CASCADE,
    worker_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,

    CONSTRAINT unique_job_worker UNIQUE (job_id, worker_id)
);
CREATE INDEX idx_applications_job ON applications (job_id, status);

04 Micro-Radius & Spatial SQL Query Blueprints

Because domestic workers (maids, cooks, gardeners) require micro-radii (500m to 3km) while commercial technicians travel 5km to 15km, the SQL query dynamically adjusts radius parameters:

1. Hyperlocal Proximity Search Query (with Inline Distance Calculation)

-- Find all available Maids or Gardeners within 3 KM of a Homeowner's Apartment
-- Input Homeowner Coordinates: Longitude = 77.3639, Latitude = 28.6080
SELECT 
    wp.karigar_id,
    u.name AS worker_name,
    u.phone AS worker_phone,
    wp.primary_trade,
    wp.expected_wage,
    wp.wage_type,
    wp.verification_badges->>'aadhaar_verified' AS is_verified,
    wp.verification_badges->>'skill_badge' AS skill_rating,
    ROUND(ST_Distance(wp.location, ST_MakePoint(77.3639, 28.6080)::geography)) AS distance_meters
FROM worker_profiles wp
JOIN users u ON wp.user_id = u.id
WHERE wp.is_available = TRUE
  AND wp.primary_trade IN ('House Maid', 'Cook', 'Gardener / Mali')
  AND ST_DWithin(wp.location, ST_MakePoint(77.3639, 28.6080)::geography, 3000) -- 3000 Meters = 3 KM
ORDER BY distance_meters ASC;

2. Django ORM Implementation (GeoDjango)

from django.contrib.gis.geos import Point
from django.contrib.gis.measure import D
from .models import Job, WorkerProfile

def search_nearby_jobs(lng: float, lat: float, category: str, radius_km: float = 5.0):
    user_location = Point(lng, lat, srid=4326) # WGS-84 Point
    
    # Executes ST_DWithin on the PostGIS GiST index automatically!
    nearby_jobs = Job.objects.filter(
        location__distance_lte=(user_location, D(km=radius_km)),
        status='active'
    )
    if category and category != 'all':
        nearby_jobs = nearby_jobs.filter(category__iexact=category)
        
    return nearby_jobs.distance(user_location).order_by('distance')

05 AI-Powered Role-Specific MCQ Screening (Gemini Flash)

When a worker registers and picks their trade (e.g., Electrician, Driver, or Gardener), the system dynamically triggers a 3-question MCQ quiz to assess technical competence and award a verified skill badge.

AI Screening Pipeline (Execution Latency < 1.2 Seconds)
1. Prompt Construction
Worker selects Trade + Language (Hindi/English). Django feeds trade taxonomy to Gemini 2.0 Flash with a strict JSON response schema.
2. On-Site Practical MCQs
Gemini generates 3 real-world troubleshooting questions (safety, tools, common mistakes) tailored to Indian working conditions.
3. Badge Award
Worker submits answers. If score ≥ 2/3, PostgreSQL updates verification_badges->>'mcq_verified' = true.

Python AI Service Implementation (`core/ai_service.py`)

import os, json
import google.generativeai as genai

genai.configure(api_key=os.getenv("GEMINI_API_KEY"))

def generate_screening_mcqs(trade: str, language: str = "hi"):
    lang_name = "Hindi (हिंदी)" if language == "hi" else "English"
    
    prompt = f"""
    Generate 3 practical on-site multiple-choice questions for evaluating a candidate in India applying as: '{trade}'.
    Language: {lang_name}. Focus on safety, tool usage, and common mistakes.
    Output MUST be a strict JSON array matching this format:
    [
      {{"id": 1, "q": "Question text", "options": ["A", "B", "C", "D"], "correct": 0, "exp": "Explanation"}}
    ]
    """
    model = genai.GenerativeModel(
        model_name="gemini-1.5-flash",
        generation_config={"response_mime_type": "application/json", "temperature": 0.3}
    )
    response = model.generate_content(prompt)
    return json.loads(response.text)

06 Trust, Safety & DigiLocker Verification Architecture

For domestic hiring (maids, cooks, babysitters), trust is the deciding factor. However, forcing DigiLocker at step 1 causes a 70%+ drop-off. Rojgar Setu implements a Progressive Trust Funnel:

Funnel Stage Target User Verification Mechanism Friction Level Trust Output
1. Registration Workers & Households Mobile Number + 4-digit SMS OTP Zero (15 Secs) Verified Phone Account
2. Skill Check Karigars / Trades 3 AI-generated MCQs (Gemini) Minimal (45 Secs) "Skills Tested ★" Badge
3. Govt ID (Optional) Domestic Workers / Drivers DigiLocker OAuth (Aadhaar / Driving License) or Parivahan API Medium (2 Mins) "Aadhaar Verified ✓" Green Tick Badge (3x higher hiring rate)
4. Business Entity MSME Employers / Contractors 15-Digit GSTIN or Udyam Registration Lookup Low (Instant) "Verified Enterprise Employer" Badge

07 End-to-End User Workflows (Visual Flow)

A. Domestic Household Workflow (Hiring a Maid or Gardener)

  1. Resident Signup: Homeowner logs in with Phone + OTP. Enters Colony/Society name (e.g. "Sector 14, RWA Colony").
  2. Browse / Post: Resident opens "Maids & Home Helpers" category. Sees cards of nearby workers sorted by distance (500m away, 1.2km away) with "Aadhaar Verified ✓" badges and neighbor star ratings.
  3. Direct Connect: Clicks "WhatsApp Chat". Opens pre-drafted message: "Hello Sunita-ji, I live in Sector 14. We need morning cleaning help from 8 AM. Are you available?"
  4. Hiring Confirmation: Resident marks worker as hired on the app. Leaves a 5-star rating after 1 week.

B. Commercial Contractor Workflow (Hiring 5 Site Electricians)

  1. Contractor Post: Contractor posts "Need 5 Commercial Electricians for 3-Phase Site Wiring", Wage: ₹800/day, Location pin in Delhi.
  2. Automated Match: PostGIS spatial query alerts registered electricians within 10 km.
  3. Review & Call: Contractor opens applicant dashboard, checks AI MCQ scores (3/3), and dials the worker directly via one-click telephony.
